# KAUT Data Contract (schema_version 1)

> Normative specification of everything KAUT writes to disk. Changes after Phase 0 must be
> **additive**: new OPTIONAL keys, new sections, new INDEX sections. Renaming, retyping, or
> repurposing an existing key is breaking and requires the migration path
> (snapshot tag → migrate → smoke test → auto-rollback; HANDBOOK §14).

## 1. Store layout

```
<root>/                        ← default ~/.kaut/<project-id>, discovery: env → pointer → derived
├── .git/                      ← the store's own private git (no remote); author "KAUT <kaut@local>"
├── .gitignore                 ← ".lock/", "*.tmp"
├── kaut.config.json          ← per-project bindings (§5)
├── INDEX.md                   ← generated catalog (§4)
├── map/                       ← L0 (script-generated; Phase 1)
├── domains/                   ← L1 thin notes
├── decisions/                 ← L3 the "why"
├── flows/                     ← L2 (deferred; scanned if present)
└── obligations.jsonl          ← append-only gap log (§7)
```

## 2. Fact document

A fact is a Markdown file under a layer directory with restricted-YAML frontmatter (§3).

```markdown
---
id: domains/routing              # REQUIRED. == store-relative path without .md
title: Routing — where routes live   # REQUIRED. One line
sources:                         # REQUIRED. ≥1 typed source (§2.1)
    - file:src/router/routes.ts
    - file-glob:packages/core/src/utils/**
derived_from_commit: <full sha>  # REQUIRED. Commit the fact was true at (merge-base anchored)
harvested: 2026-06-10            # REQUIRED. ISO date of derivation
engine: manual@0.1.0             # REQUIRED. collector@engine-version; "manual" for hand-written
tickets: []                      # OPTIONAL. Ticket keys
trust: T1                        # REQUIRED. T0|T1|T2|T3|T4 — headline = min over sections
checks: []                       # REQUIRED (may be empty). Passed check ids, e.g. micro-verify@1
schema_version: 1                # REQUIRED
---

## Pointers
<!-- sources: file:src/router/routes.ts -->
<!-- trust: T1 -->

…content…
```

Rules:

- **No source — no claim.** Unsourced text cannot enter the store.
- `id` must equal the store-relative path without `.md`; the directory IS the layer.
- Unknown frontmatter keys are preserved and ignored (tolerant reader).
- Full provenance (`trust`, `checks`, `engine`) is written at EVERY assurance level, even
  while nothing reads it yet (level switches need no migration).

### 2.1 Typed sources

```
source := "file:" path          ; one file, relative to the project repo root
        | "file-glob:" glob     ; glob, relative to the project repo root
        | "ticket:" key         ; e.g. ticket:TICKET-16576
        | "user:" iso-date      ; a human statement, dated
```

- Only `file:` / `file-glob:` participate in freshness (git diff) and the `broken` rule.
  `ticket:` / `user:` are provenance-only — they can never go stale or break.
- An OpenAPI-style fragment (`file:openapi/api.yaml#/components/...`) is stripped to the
  file path for diffing; the fragment stays in the raw value for human reference.

### 2.2 Per-section bindings and append blocks (written from Phase 2; defined now)

- Section binding, immediately after a `##` heading:
  `<!-- sources: <comma-separated typed sources> -->` and `<!-- trust: T<n> ... -->`.
- Distill-append block opener: `<!-- derived: <commit> -->` — freshness is evaluated per
  block when present.

### 2.3 Quote fences (the ONLY place verbatim external text may exist at rest)

````markdown
```kaut-quote ticket=TICKET-15781 date=2026-03-02
Length-capped, sanitized quotation (no imperatives, no URLs).
```
````

## 3. Restricted-YAML frontmatter subset

Exactly these constructs (anything else is a parse error with a line number — the parser
never guesses):

```
key: scalar                 # scalar = rest of line, trimmed; no quoting needed
key:                        # opens a block list
    - item
key: []                     # inline empty list
key: [a, b]                 # inline list, comma-separated, no quoting/nesting
# full-line comment         # and trailing " # comment" is stripped on any line
```

Not supported (use is a contract violation): nested maps, multiline scalars, anchors,
quoted strings, empty scalar values (a bare `key:` means an empty list).

## 4. INDEX.md

```markdown
<!-- GENERATED by kaut index — do not edit. -->
# KAUT INDEX — <project-id>

| id | title | trust | derived_from_commit | sources(files) |
|---|---|---|---|---|
| domains/routing | Routing — where routes live | T1 | <sha, first 12> | 2 |

## Gaps

(none)

## Invalid

(none)
```

- **No freshness column** — verdicts are computed at read time, never stored (§11).
- `sources(files)` = count of file-typed sources.
- `Gaps` = declared-but-missing topics (writers arrive Phase 1+; the section is part of the
  contract now). `Invalid` = docs that failed validation, with reasons — visible, never
  silently dropped.
- Rows are sorted by `id`; `|` inside titles is escaped as `\|`.

## 5. kaut.config.json

Created by bootstrap with project bindings; never overwritten by re-bootstrap. Keys:
`schema` (1), `project` {id, repo, remote, mainBranch}, `assurance` {level 1–5},
`language`, `map` {routes, stores, packages}, `sources` {openapi, i18n, e2e, mocks},
`runtime` {devMockCommand, baseUrl}, `tickets` {pattern, mcp, readOnly},
`collectors` {default, onDemand}, `trust` {sourceOverrides, categoryFloors}.
There is deliberately NO `knowledge.root` key — the root is resolved by the discovery
chain (env → pointer → derived), never by the config that lives inside it.

## 6. `.kaut.json` pointer (in the project repo, ignored via `.git/info/exclude`)

```json
{
    "schema": 1,
    "projectId": "<id>",
    "root": "/absolute/path/to/store",
    "engine": "/absolute/path/to/engine"
}
```

Absolute paths only (no `~`). Losing the pointer is harmless: derivation resolves the same
store.

## 7. obligations.jsonl

Append-only, one JSON object per line (writers arrive Phase 1+):

```json
{ "ts": "2026-06-10T12:00:00Z", "type": "miss|implicit-miss|stale-hit|compaction", "topic": "…", "branch": "…", "paths": [] }
```

## 8. Store git conventions

- Repo-local identity `KAUT <kaut@local>`; `commit.gpgsign false`.
- Messages: `kaut: bootstrap v<engine-version>`, `kaut: index-gen (N docs, M files changed)`,
  `kaut: add <id> (manual)`.
- Every engine-driven mutation = exactly one commit. `kaut index` commits all staged
  changes — manual edits ride along (snapshot guarantee).

## 9. Lockfile protocol

- Lock = `mkdir <root>/.lock` (atomic); owner metadata in `.lock/owner.json`
  `{ pid, startedAt, op }`.
- Busy: retry with backoff up to 10 s, then exit code 2.
- Steal only when the owner pid is dead AND the lock is older than 15 min.
- Release = remove the directory (always in `finally`).

## 10. Versioning

- Documents: `schema_version: 1`. Config/pointer: `"schema": 1`. Engine: `VERSION` file,
  referenced in fact provenance as `<collector>@<engine-version>`.
- CLI exit codes: 0 ok · 1 validation/doctor failure · 2 lock busy · 3 environment missing.

## Phase 1 additions (schema_version 1, additive)

Everything below was added with engine v0.2.0. It introduces no breaking change: no existing
key is renamed or retyped. `disputed` is a new OPTIONAL frontmatter flag; the rest are read-time
behaviours and new generated artifacts.

### 11. Freshness verdicts (computed at read, never stored)

```
verdict  := healthy | disputed | broken | stale | branch-advisory
priority := disputed > broken > stale > branch-advisory   ; at most ONE renders
```

- **anchor** = `merge-base(HEAD, <mainRef>)` where `mainRef` = `origin/<main>` if present, else
  local `<main>`, else `HEAD`. Stored verdicts depend only on the anchor, so switching branches
  never flaps them.
- **broken** — a `file:`/`file-glob:` source matches ZERO paths in the anchor tree
  (`git ls-tree -r <anchor>`). Evaluated per-pattern/per-section. A broken pattern cannot be
  diffed, so it never reports "fresh" (renames/typos are caught, not hidden).
- **stale** — `git diff --name-only <derived>..<anchor>` over the file sources is non-empty, OR
  (err-toward-stale) the `derived_from_commit` is unknown to the repo or not an ancestor of the
  anchor.
- **branch-advisory** — EPHEMERAL: committed changes `<anchor>..HEAD` plus uncommitted edits
  (`git diff --name-only HEAD` ∪ `git ls-files --others`) intersect the sources. Computed at
  read, never written to disk.
- **disputed** — optional frontmatter `disputed: true` (writers arrive Phase 2+); rendered with
  top priority when present.
- Only `file:`/`file-glob:` participate; `ticket:`/`user:` never go stale or broken.
- Per-section: a section's `<!-- sources -->` binding scopes its own evaluation; a section
  without one inherits the doc-level `sources`. Doc verdict = worst section; affected = union.

### 12. Lookup block (the agent-facing read format)

```markdown
# kaut: <id>
trust: <T> (<mechanical|claimed>) · derived: <sha12> · <verdict phrase>

<body: full when healthy; on any verdict, partial — only ## Invariants / ## Decisions / ## Why,
 plus an "affected files:" line and a "(N sections omitted — re-derive from code)" note>

[hint: …]   ← at most one, only for claimed (T2+) content or a non-fresh regenerable map
```

- Two reader classes: T0/T1 = `mechanical`, T2+ = `claimed`.
- A healthy T0/T1 doc renders with body only — no verdict warning, no hint (silent by default).
- `lookup` with no id prints the INDEX (catalog). An unknown id prints `miss: no doc "<id>"`
  with nearest-match ids and exits 0 (a miss is a valid answer, not an error).

### 13. `journal.jsonl` (store root, untracked)

Append-only usage telemetry — the mechanical layer of the usefulness journal (HANDBOOK §12).
One JSON object per line; written by `lookup`/`map`/`note` and the commit
chokepoint, with no lock (O_APPEND). It is NOT knowledge (gitignored) and NOT the obligations
queue (Phase 2). `op` records:

```json
{ "ts": "<iso>", "op": "lookup", "topic": "<id>", "verdict": "<verdict|null>", "trust": "<T|null>", "altitude": "landscape|component|endpoint", "mode": "full|partial|miss|catalog|invalid|withheld", "branch": "<name>" }
{ "ts": "<iso>", "op": "map",   "topic": "<id>", "verdict": null, "trust": "T0", "mode": "full", "branch": "<name>" }
{ "ts": "<iso>", "op": "write", "topic": "<id>", "tier": "agent|owner-approved|free" }
{ "ts": "<iso>", "op": "outcome", "topic": "<id>", "result": "trusted|confirmed|insufficient|stale-misled", "note": "<optional>", "branch": "<name>" }
```

- **`altitude`** (on `op:lookup`, doc reads) — the coverage band (§25), so the digest can split coarse
  vs precise reads. Records written before this field existed simply lack it.
- **`op:outcome`** — the VALUE signal, written by `kaut note <topic> <result>` (a knowledge-update
  skill emits it after a session USED a doc). The four results are objective in-session follow-ups, not
  ratings: `trusted` (used it, did not read code), `confirmed` (trusted but verified in code anyway),
  `insufficient` (did not answer, fell back to code), `stale-misled` (was wrong, sent the session astray).
  Honor-system (the engine cannot prove it); misses are already captured by `lookup` `mode:miss`. A typo'd
  result is rejected, never logged. This turns the journal's *reach* record into a *value* record.

### 14. L0 map documents (T0, machine-generated)

Regenerated wholesale by `kaut map` — never hand-edited, never appended.

- `map/routes.md` — `engine: route-map@<ver>`, `trust: T0`,
  `sources: file:src/router/routes.ts, file:packages/core/src/utils/constants.ts`. Body: a pipe
  table `| path | name | view | package | guard |`, children flattened (`<parent>/<child>`),
  routes in source order. The generator resolves every `ROUTER_PATH.<Key>.Path` to its literal
  and aborts (writing nothing) if any `path:` entry fails to resolve.
- `map/packages.md` — `engine: pkg-graph@<ver>`, `trust: T0`,
  `sources: file-glob:packages/*/src/**, file:tsconfig.base.json`. Body: `| package | depends on
  | imported by |` (one row per package, alphabetical; weight = importing-file count).

### 15. Section-heading convention (recommendation, not validated)

`## Pointers` (code-derived locations) · `## Invariants` · `## Decisions` (the why; cite ticket
keys) · `## Notes`. A non-healthy lookup keeps Invariants/Decisions/Why and omits the rest.

## v0.2.1 additions (additive)

### 16. `tampered` verdict — out-of-pipeline edits are withheld

```
verdict  := healthy | tampered | disputed | broken | stale | branch-advisory
priority := tampered > disputed > broken > stale > branch-advisory
journal.mode += withheld
```

Every byte the read path serves must come from a KAUT commit (the store's own git). A doc
file that differs from `HEAD` of the store — modified, untracked-added, or deleted — is
**tampered**: `lookup` withholds its content entirely (no body, no frontmatter echo; the file
is not even parsed), renders only the verdict line plus heal instructions, and journals
`mode: "withheld"`. Unlike the other verdicts this one is computed from STORE git state, not
from the project repo. `doctor` gains `store-clean` (FAIL when the store working tree is
dirty) and `store-authors` (WARN on non-KAUT commit authors — spoofable, catches accidents
not attackers). Heal: `git checkout -- <file>` in the store to discard, `kaut index` to
accept into the pipeline (records provenance), `kaut map` for regenerable `map/` docs.
Rationale: the docs are injected into agent context; an unprovenanced edit is an injection
channel, and withholding beats serving.

## v0.3.0 additions (additive — workspace thin slice)

### 17. `repo:` typed source (cross-repo, existence-only)

```
source := … | "repo:" name ":file:" path     ; name = workspace member repo name
```

Resolved through the workspace registry (§21) to the member repo's absolute path and
checked EXISTENCE-ONLY at that repo's `HEAD`: missing path ⇒ `broken`; present ⇒ never
stale (full multi-anchor staleness is post-pilot). Registry or repo unresolvable ⇒ the doc
goes `stale` with an "unverifiable" note — err toward stale, never toward fresh. `repo:`
sources do not count in the INDEX `sources(files)` column and are skipped by doctor's
file-existence WARN (the stale path owns them).

### 18. `project.anchorRepo` (OPTIONAL config key)

When a store's `kaut.config.json` declares `project.anchorRepo` (absolute path), the
freshness context for `stale`/`lookup`/`map` and doctor's file-source check is built
against THAT repo instead of the cwd repo — e.g. a workspace SYSTEM store anchored to the
launcher repo while being read from the conductor repo. Absent key = historical behavior,
byte-identical. Journal `branch` still records the reader's (cwd) branch.

### 19. `map.collectors` + `composemap` (OPTIONAL config keys)

`map.collectors` selects the L0 collectors `kaut map` runs: `routemap` | `pkggraph` |
`composemap`; absent = the historical `["routemap", "pkggraph"]`; `[]` = nothing to do.
`composemap` parses the compose file (`map.composeFile`, default `docker-compose.yml`) in
the store's anchor repo into `map/services.md` (`engine: compose-map@<ver>`, trust T0,
pipe table `| service | image | ports | depends_on | container_name |`). Subset parser
with a scoped self-check: the parsed service count must equal the `services:` block's own
2-space key count, else it refuses to write (the same abort-rather-than-emit-partial
discipline as the route-map adapter).

Adapter locations are CONFIG, not code (engine-vs-data principle): OPTIONAL
`map.routesFile` / `map.constantsFile` (routemap) and `map.packagesDir` (pkggraph) override
the built-in STACK defaults. The bootstrap seed config carries no project-specific literals
(tickets.pattern/mcp seeded null; sources/runtime empty) — project values are data, edited
into `kaut.config.json` per project; pre-0.3.0 configs are never rewritten.

### 20. Layer dirs extension

`LAYER_DIRS` += `contracts/`, `runbook/`, `bootstrap/` (scanned when present; the
directory IS the layer, id = path rule unchanged). Stores without these dirs scan exactly
as before.

### 21. Workspace registry (`~/.kaut/workspaces/<name>.json`)

A DERIVED copy generated by `kaut workspace init --manifest <path>` from a conductor
manifest (the single source of truth, owned by the orchestration framework): `{schema: 1,
name, generatedBy, manifestPath, conductorRepo, systemStore{id, root, anchorRepo,
composeFile}, repos[{name, path, projectId, storeRoot, storePolicy}]}`. Regenerated
wholesale on every init; consumed by the `repo:` source resolver. A repo with
`storePolicy: "do-not-touch"` gets a registry entry and nothing else (no bootstrap, no
pointer, no working-tree files). System store id: `system-<name>--<sha8("workspace:"+name)>`
— deterministic, collision-free with the launcher's own store. Env seams: `KAUT_HOME`
relocates the whole `~/.kaut` base; `KAUT_WORKSPACES_DIR` relocates just the registries.

## OKF conformance (schema_version 1, additive — engine 0.3.x)

KAUT is a conformant producer/consumer of the **Open Knowledge Format** (OKF v0.1 — typed markdown +
YAML frontmatter + cross-link graph; vendor-neutral). The relationship is *Hibernate:JPA :: KAUT:OKF*
— KAUT IMPLEMENTS the format and EXTENDS it with the freshness/trust/provenance OKF leaves out of
scope. Additive only: no existing key is renamed or retyped. The full frozen field mapping + provenance
live in the maintainers' private hub (a development-process doc, not in this repo).

### 22. `type` — the one OKF-required field (OPTIONAL here, == the layer)

```
type: <layer>          # OPTIONAL. == the doc's layer = first segment of its id (its directory)
```

- OKF requires every concept to carry a `type`. KAUT's layer dir already IS that type, so `type` is
  **derivable from the path** (store-discipline litmus → not forced into stored docs): a doc that omits
  `type:` is read AS `typeForId(id)` = `id.split('/')[0]`. Pre-0.3.x docs are never rewritten.
- When **present**, `type` MUST equal the layer (`domains/x` with `type: decisions` is invalid — caught
  by `validateDoc`, listed under `Invalid`, never silently accepted).
- **Engine-generated docs stamp it** for in-place external conformance: `map/*` (`route-map`,
  `pkg-graph`, `compose-map`) emit `type: map`. Serialization places `type` right after `id`.
- OKF reader rules KAUT already satisfies as a **consumer**: unknown frontmatter keys are preserved,
  not rejected (§2 tolerant reader); a `broken` source / `Gaps` entry models OKF's "broken link =
  not-yet-written", which consumers must tolerate.

### 23. KAUT's required fields ride as OKF extensions (the moat)

OKF v0.1 has no freshness/trust/provenance/validation (explicitly out of scope) and **normatively
protects extension keys** ("producers MAY include additional keys; consumers SHOULD preserve unknown
keys… SHOULD NOT reject"). So KAUT's `trust` / `derived_from_commit` / typed `sources` / `engine` /
`checks` / `schema_version` / `disputed` are all valid OKF extensions; OKF's recommended
`title`/`resource`/`timestamp` are subsumed by our `title` / typed `sources` (superset of `resource`) /
`harvested` (+ the verifiable `derived_from_commit`). Identity stays in the engine — OKF is the
portability surface, not the identity. Import/export adapters (`kaut okf …`) are deferred to a driver
(B7-β); this section is the in-place producer surface (B7-α).

## Write grants — the layered promotion gate (schema_version 1, additive — engine 0.3.x)

Design intent: operational deltas a session has runtime-verified may be agent-written without a per-item
owner ask; semantic/architectural layers stay owner-gated. Policy is DATA, additive: a new OPTIONAL
`writePolicy` map flows manifest → registry → the engine. No existing key is renamed/retyped.

### 24. `writePolicy` (registry/manifest, OPTIONAL) + the commit-chokepoint gate

```
writePolicy := { "<layer>": "agent"|"owner", "*": "agent"|"owner" }   # per-layer grant + default
```

- **Source:** `defaults.writePolicy` in the conductor manifest (optional `repos[].writePolicy` override);
  `kaut workspace init` copies it into each registry `repos[]` entry AND into `systemStore` (runbooks live
  in the system store). Older registries simply lack the key.
- **Enforced at the single commit chokepoint** (`gitstore.commitAll`), through which every write path
  (bootstrap/index/map/workspace) funnels — so the gate is **not bypassable** by choosing another command.
  Before staging, a changed fact doc (`*.md` under a layer dir) whose grant resolves to `owner` is REFUSED
  unless `--approve` is passed; refusal aborts the whole commit (exit 1, nothing staged or committed). An
  `--approve`d owner-tier write is recorded in the store commit message (`… [owner-approved: <ids>]`) — store
  git history is the durable audit + rollback — and journalled (`op:'write'`, `tier`).
- **`map/*` by PROVENANCE, not layer name:** an adapter-generated map doc (`engine: compose-map@` /
  `route-map@` / `pkg-graph@`) takes the configured `map` grant; a hand-authored map doc (any other
  `engine:`) is forced `owner` when map is governed. The discriminator is the existing `engine:` field.
- **Creation-distinction (Mechanism A):** an UPDATE to an agent-tier doc, and the CREATION of a type that
  already EXISTS elsewhere in the deployment (the same id committed in any sibling store of the registry),
  stay Tier A (auto). Creating a NOVEL id — absent from this store's `HEAD` AND from every sibling store —
  upgrades to `owner` (an offer needing `--approve`), capping agent-driven doc proliferation + naming drift.
  The first repo to establish a type is owner-gated; from the second onward the pattern is inherited. `map`
  is EXEMPT (adapter map is deterministic, a fixed id-set, already gated by provenance above — not the
  free-form authoring drift this targets).
- **`storePolicy: do-not-touch` has ABSOLUTE precedence** — such a store takes no pipeline write at all,
  even agent-tier, even with `--approve`.
- **Open-until-configured:** a store no registry knows, OR a registry entry with no `writePolicy`, OR a
  layer the map does not cover (no `<layer>` and no `*`), grants the write (free) — so adding the engine
  reader is byte-identical to pre-gate behaviour until a `writePolicy` is set.
- **Honor-system, NOT over-claimed:** the Tier-A predicate (a Tier-A auto-write only when the writing
  session runtime-verified the fact) is agent-side discipline; the engine cannot prove in-session
  verification, so it is upheld by discipline + reading-is-repair + doctor, NOT by this gate. The gate
  mechanically enforces only the layer/provenance/do-not-touch policy and the approval flag. The journal
  `tier` is a grant label, not proof of verification. (This is NOT "the only write surface" — SCHEMA §8's
  multi-command commit reality stands; the gate sits at the shared chokepoint they all use.)

## Coverage signal — `altitude` (lookup surface, additive — engine 0.3.x)

### 25. `altitude` — a second axis on the lookup verdict surface, orthogonal to freshness

```
altitude := { band: "landscape"|"component"|"endpoint", distinctRepos: int, basis: str, confirmDirective: bool }
```

- **What:** at what ZOOM does a doc describe the system — `landscape` (cross-repo overview), `component`
  (one repo's internals), `endpoint` (a specific route/handler/field). Freshness answers "is it current?";
  altitude answers "is it at the granularity your question needs?". Closes a gap benchmarking surfaced:
  a HEALTHY-but-coarse doc read as coverage for a fine-grained question, with nothing to warn the reader.
- **Back-derived, nothing stored** (store-discipline litmus — like the OKF `type`). `altitudeFor({id, sources})`
  is pure and NEVER sees the question (a property of the DOC), so it composes with topic-addressed lookup and
  cannot drift into retrieval/RAG. Derivation is **layer-primary**: coarse layers (`map`/`contracts`/`flows`)
  ⇒ `landscape` iff their sources span ≥2 distinct repos else `component`; fine layers (`domains`/`runbook`)
  ⇒ `endpoint` iff sourced by ≤2 pinpoint `file:`/`repo:…:file:` paths and no `file-glob:`, else `component`;
  meta layers (`decisions`/`bootstrap`) ⇒ `component`. Repo-span is a tie-breaker **only within coarse
  layers** — a fine doc whose globs span repos stays `component` (the rejected naive "≥2 repos ⇒ landscape").
- **Surface:** `lookup --json` always carries the `altitude` object (every band) so an MCP/orchestrator can
  gate confident extrapolation by the `confirmDirective` flag. `lookup` TEXT renders a scope line ONLY for a
  `landscape` doc — its §4.2 confirm-in-code directive; `component`/`endpoint` stay silent (one-verdict law
  intact — altitude is a parallel scope line, NOT a second status phrase). Fires independent of freshness:
  a HEALTHY `landscape` doc still gets the directive (the whole point).
- **Optional override (DEFERRED, not built):** an explicit `altitude:` frontmatter key for the rare doc whose
  mechanical band is wrong (e.g. a cross-repo `flows/` doc whose declared sources cite one repo). Until then
  the mechanical value is authoritative. (Design note in the maintainers' private hub.)

## Usage digest — reading the telemetry back (additive — engine 0.3.x)

### 26. `kaut digest [--workspace <name>] [--since <ISO-date>] [--json]`

Aggregates the §13 journals across every store of a workspace (all registered workspaces when
`--workspace` is omitted) into one picture — the substrate for the still-open KAUT VALUE question
(tracked in the maintainers' private hub). Read-only telemetry: no lock, no store write, tolerates a
non-store cwd; reads store roots straight from the registry (so even `do-not-touch` stores report).

- **Reach:** lookups by mode, **hit/miss** (coverage), `verdict` distribution (how often a read hit a
  *stale* doc = rot-on-contact), `trust`, `altitude` (coarse vs precise).
- **Self-maintenance:** writes by `tier` (`agent` auto vs `owner-approved`).
- **Value:** `op:outcome` distribution (`trusted`/`confirmed`/`insufficient`/`stale-misled`) — present only
  where sessions ran `kaut note`. Misses (`mode:miss`) are the mechanical coverage-gap signal alongside it.
- **Top topics** (by reads, flagged with miss/stale counts + per-topic outcomes) and a **per-store**
  breakdown. `aggregate`/`renderDigest` (`lib/digest.mjs`) are pure folds over the records; the CLI only
  sweeps + reads. Honest limits: a session that never calls `lookup` logs nothing (non-consultation is
  invisible); the value signal is honor-system. Strong on mechanical reach/freshness, suggestive on value.
